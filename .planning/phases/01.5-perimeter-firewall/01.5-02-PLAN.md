<objective>
Desplegar la VM OPNsense en Host 6, instalarla manualmente (el instalador requiere interacción con consola), y configurar WAN/LAN/NAT/Snort vía la web UI. El script automatiza la preparación (descarga ISO, creación VM, definición de NICs) — el operador completa la instalación en consola y la configuración inicial en la web UI.

Purpose: OPNsense no tiene instalación desatendida robusta para este escenario de doble NIC sobre bridges virtuales. El valor del script es eliminar los pasos repetibles (qm create, iso download, network assignment) y dejar al operador solo con los pasos que genuinamente requieren GUI o consola interactiva.

Output: deploy-opnsense-vm.sh (automatiza prep de VM), más los pasos de consola + web UI que el operador ejecuta en el checkpoint.
</objective>

    Variables configurables al inicio del script (con valores por defecto documentados):
    - VMID=700          # VMID para OPNsense VM en Host 6 (elegir fuera del rango Phase 2: 101-105, Phase 3: 601)
    - HOST6_NODE=pve6   # Nombre del nodo Proxmox de Host 6 (ajustar si el nodo tiene nombre diferente)
    - STORAGE=local-lvm # Pool de almacenamiento (mismo que todas las VMs del lab)
    - DISK_SIZE=16G     # Disco OPNsense (8G mínimo; 16G deja margen para logs Snort)
    - RAM=1024          # 1 GB RAM para OPNsense base
    - VCPU=2            # 2 vCPU
    - LAN_BRIDGE=vmbr_lan  # Bridge LAN — operador cambia a 'vmbr0' si usó --mode=reuse-vmbr0 en Plan 01
    - OPNSENSE_VERSION=24.7  # Versión OPNsense a descargar (verificar opnsense.org al ejecutar)
    - ISO_URL="https://mirror.ams1.nl.leaseweb.net/opnsense/releases/${OPNSENSE_VERSION}/OPNsense-${OPNSENSE_VERSION}-dvd-amd64.iso.bz2"
    - ISO_PATH="/var/lib/vz/template/iso/opnsense-${OPNSENSE_VERSION}-amd64.iso"

    Pasos en --apply:

    1. DESCARGAR ISO si no existe ya en ISO_PATH:
       ```bash
       if [[ ! -f "$ISO_PATH" ]]; then
           wget -O "${ISO_PATH}.bz2" "$ISO_URL"
           bunzip2 "${ISO_PATH}.bz2"
       else
           echo "ISO ya existe en $ISO_PATH — skip descarga"
       fi
       ```
       El script corre en el NODO HOST 6 (el operador hace SSH a pve6 antes de ejecutarlo). No usar pvesh ni API de otro nodo.

    2. CREAR VM con qm create:
       ```bash
       qm create $VMID \
           --name opnsense-gw \
           --memory $RAM \
           --cores $VCPU \
           --net0 virtio,bridge=vmbr_wan \
           --net1 virtio,bridge=$LAN_BRIDGE \
           --ostype other \
           --scsihw virtio-scsi-pci \
           --boot order=ide2 \
           --ide2 local:iso/opnsense-${OPNSENSE_VERSION}-amd64.iso,media=cdrom \
           --node $HOST6_NODE
       ```
       Si VMID ya existe: imprimir error claro "VMID $VMID ya existe — cambiar variable VMID en el script" y exit 1.

    3. AÑADIR disco de sistema:
       ```bash
       qm set $VMID --scsi0 ${STORAGE}:${DISK_SIZE}
       ```

    4. CONFIGURAR opciones de arranque:
       ```bash
       qm set $VMID --boot order='ide2;scsi0'
       qm set $VMID --vga std
       ```
       VGA std es necesario para que el instalador OPNsense muestre correctamente en noVNC de Proxmox.

    5. INICIAR VM:
       ```bash
       qm start $VMID
       echo "VM $VMID iniciada — abrir consola noVNC en Proxmox web UI: https://<HOST6-IP>:8006/?console=kvm&vmid=$VMID"
       echo "Seguir los pasos de instalación manual en el checkpoint."
       ```

    6. En dry-run: imprimir todos los comandos qm que se ejecutarían (con las variables resueltas) y la URL de ISO a descargar, sin ejecutar nada.

    Añadir en cabecera del script:
    - Referencia a ADR-001 para la topología
    - Instrucción: "ejecutar en Host 6 (ssh root@pve6) — no en el nodo de control"
    - Nota: ajustar LAN_BRIDGE si el Plan 01 usó --mode=reuse-vmbr0 (cambiar a vmbr0)

<threat_model>
## Trust Boundaries

| Boundary | Descripción |
|----------|-------------|
| Internet (wlan0/vmbr_wan) → OPNsense WAN | OPNsense stateful firewall bloquea conexiones entrantes no solicitadas. WAN rule por defecto = block. |
| OPNsense LAN (10.0.0.254) → VMs del lab | Snort inline inspecciona TODO el tráfico que pasa por la interfaz LAN — tanto inter-segmento como hacia internet. |
| OPNsense console (noVNC) → acceso de configuración | La consola noVNC del Proxmox solo es accesible desde la web UI de Proxmox (10.0.0.x autenticado). No hay exposición pública. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1.5-04 | Spoofing | OPNsense WAN default credentials (root/opnsense) | mitigate | Paso D del checkpoint explícitamente requiere cambiar contraseña al primer login. Credencial va a .planning/secrets/PASSWORDS.md. |
| T-1.5-05 | Information Disclosure | Snort en modo IDS (no IPS) durante emulaciones | accept | IDS (detect-only) es correcto para lab de emulación — modo IPS bloquearía tráfico red team antes de generar telemetría. Aceptado por diseño. |
| T-1.5-06 | Denial of Service | Snort ET Open ruleset excesivo → CPU OPNsense al 100% | mitigate | OPNsense VM tiene 2 vCPU. Si CPU > 80% constante, reducir ruleset en Services → Intrusion Detection → Rules (desactivar categorías menos relevantes: policy, games, etc.). Dejar activas: emerging-exploit, emerging-malware, emerging-scan, emerging-trojan. |
| T-1.5-SC | Tampering | Descarga ISO OPNsense desde mirror público | mitigate | Verificar SHA256 del ISO contra checksums publicados en opnsense.org/download antes de arrancar la VM. Paso añadir al script: `sha256sum $ISO_PATH` y link a checksums. |
