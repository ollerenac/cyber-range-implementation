      declare -A WINDOWS_VMS=(
        ["dc01"]="10.0.0.11:server"

        ["sql01"]="10.0.0.13:server"
        ["ws01"]="10.0.0.14:workstation"
        ["ws02"]="10.0.0.15:workstation"
      )

    Per-VM function enroll_windows_vm(name, ip, role):
      1. Copy CA cert to VM via pwsh Copy-Item over PSSession:
         pwsh -c "
           \$cred = New-Object PSCredential('Administrator', (ConvertTo-SecureString '${WINDOWS_ADMIN_PW}' -AsPlainText -Force))
           \$session = New-PSSession -ComputerName ${ip} -Credential \$cred
           Copy-Item /etc/elasticsearch/certs/ca.crt -Destination 'C:\\Temp\\ca.crt' -ToSession \$session
           Remove-PSSession \$session
         "
      2. Deliver 09-elastic-agent.ps1 via Invoke-Command with -VmRole and -FleetToken parameters:
         pwsh -c "
           \$cred = New-Object PSCredential('Administrator', (ConvertTo-SecureString '${WINDOWS_ADMIN_PW}' -AsPlainText -Force))
           Invoke-Command -ComputerName ${ip} -Credential \$cred -FilePath ./scripts/windows/setup/09-elastic-agent.ps1 \
             -ArgumentList '${role}', '${FLEET_TOKEN}'
         "
      3. Log success/failure per VM

    Main loop: iterate WINDOWS_VMS, call enroll_windows_vm for each. Run them SEQUENTIALLY (not parallel &)
    to avoid overwhelming the Fleet Server with simultaneous enrollments.

    After all VMs enrolled, poll Fleet API (D-19 CORRECTED endpoint from RESEARCH.md Pitfall 2):

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| elastic-vm → Windows VMs (WinRM port 5985) | Administrator credentials sent over HTTP on isolated MGMT subnet |
| elastic-vm → Kali (SSH) | SSH key authentication; elastic-agent runs as root for eBPF |
| Elastic Agents → Fleet Server (port 8220) | TLS with lab CA cert; enrollment token is one-time use conceptually |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-08 | Information Disclosure | WINDOWS_ADMIN_PW in env var on elastic-vm | mitigate | Set in shell session only; never written to script files; never echoed; cleared after enrollment |
| T-03-09 | Information Disclosure | FLEET_TOKEN in env var | mitigate | Same: session-only env var; tokens have no TTL unless revoked; generating fresh per RESEARCH.md OQ-4 |
| T-03-10 | Tampering | WinRM HTTP (not HTTPS) on MGMT subnet | accept | MGMT subnet is isolated (no internet, no external access per D-02/D-03 Phase 1); HTTP WinRM acceptable in this lab scope per RESEARCH.md OQ-5 |
| T-03-11 | Elevation of Privilege | elastic-agent running as SYSTEM on Windows | accept | Required behavior; WinRM already runs elevated; elastic-agent install requires SYSTEM for EDR hooks |
| T-03-SC | Tampering | elastic-agent .deb from elastic.co | accept | Official Elastic artifact; version pinned to 8.19.16; downloaded via HTTPS from elastic.co; no PyPI/npm involved |
</threat_model>
