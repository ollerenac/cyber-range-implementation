<objective>
Create the two persistent control-plane VMs on the bridges established in Plan 01: elastic-vm (Host 1) and caldera-vm (Host 6). These VMs are NEVER snapshotted and NEVER in reset_range.sh (D-10) — they are the data sink and the C2 platform. This plan provisions the VMs and base Ubuntu 22.04 OS only; service installation happens in Plans 03 (SIEM) and 04 (CALDERA).

Purpose: Both downstream service plans require a running, network-reachable Ubuntu host with the exact locked IP addresses. elastic-vm's IP (10.0.0.10) is LOCKED by D-12 because the Fleet Server TLS cert SAN bakes it in — changing it later forces CA regeneration and re-enrollment of every agent.

Output: Two qm create scripts with locked specs, a cloud-init user-data template for headless Ubuntu provisioning, and two running VMs reachable over SSH on MGMT.

CRITICAL VERSION NOTE: This phase pins all Elastic components to 8.19.16 (NOT the 8.17.x referenced in older CONTEXT.md/STATE.md — 8.17.x is EOL since Aug 2025 per RESEARCH §State of the Art). VM provisioning here is version-agnostic, but the elastic-vm disk (200 GB) and RAM (14 GB per D-NEW-01) are sized for the 8.19.16 stack.
</objective>
